# Remotion 版式组件库使用指南

## 固定层

- 画布：1080×1440，30fps
- 视觉：黑绿科技背景、霓虹强调色、统一标题与字幕体系
- 字幕：底部安全区、最多两行
- 音频：固定本机 Voicebox 音色，连续生成后再打轴
- 片尾：`src/template/scenes/LockedOutro.tsx` 原生场景，禁止被正文覆盖

## 正文垂直分区

所有正文组件都必须使用同一套纵向节奏，不能把主要内容堆在上半屏：

- `y=80–260`：栏目标签、主标题和简短说明。
- `y=300–980`：主内容区，卡片、关系图和流程必须延伸到这一视觉带的中下部。
- `y=1060–1150`：辅助信息条，用于补充结论、记忆句或进度，不得只放一行悬空小字。
- `y=1210–1355`：固定两行字幕安全区，正文禁止进入。

内容较少时，放大卡片并让主内容在主内容区底部对齐；内容较多时向上自然扩展。禁止通过缩小字体把内容压回顶部。

## 自适应版式

| 内容关系 | `type` | 使用条件 |
|---|---|---|
| 多个同级概念 | `overview` | 4–8 个类别、能力或结论总览 |
| 两组差异 | `compare` | 左右对比、错误/正确、前/后 |
| 连续步骤 | `process` | 3–6 个有先后关系的步骤 |
| 问题到结果 | `case` | 问题、做法、结果或三阶段案例 |
| 三因素关系 | `triangle` | 三个共同支撑一个结果的因素 |
| 完整工作流 | `workflow` | 视频后段的流程总结或记忆页 |
| 单个工具详情 | `skill_detail` | 只在确实需要讲一个工具时使用 |
| 评论互动 | `comment_cta` | 固定片尾前引导评论区领取资料、工具包或检查表 |

## 路由规则

1. 先为每段填写内容关系 `relation`：`peers` 并列、`detail` 单点拆解、`sequence` 步骤、`workflow` 完整流程、`contrast` 对比、`relationship` 关系、`case` 案例、`comment` 评论互动。系统再据此选版，不能只根据“第一阶段”等标题关键词机械套卡片。
2. 同一种自适应版式不得连续出现超过两页。
3. 一条视频至少包含三种正文版式。
4. 多次出现并列信息时，系统必须在 `bento-grid`、`index-grid` 与 `spotlight-grid` 之间切换，不能因为中间隔了一页就重新使用相同宫格。
5. 主信息与小字补充必须表达不同层次，禁止重复抄写。
6. 动画默认使用成组进入和讲到哪高亮哪；只有真正的步骤页才逐步构建。
7. 新内容先写 `content-outline.json`，由系统生成 `layout-scenes.json`；不要复制旧视频的场景类型，也不要修改 React 组件。

## 新视频生产

1. 提炼口播脚本并按语义切成场景，参照 `content-outline.example.json` 写入 `content-outline.json`。
2. 运行 `npm run apply:layouts`，把语义段落转换为真实 `type` 和对应组件字段。
3. 检查命令输出的 `layout_types`；正文达到 5 页时至少使用 3 种语义版式。
4. 运行 `npm run make` 生成固定音色、字幕和场景时长；如果正式口播、内容结构和场景旁白不是同一版，构建会在调用 Voicebox 前停止。
5. 运行 `npm run lint`。
6. 为每个场景抽取一个中间帧组成联系表；只检查少数页面不算通过。
7. 运行 `npm run make:render -- --output out/video.mp4`；该入口会先执行 `npm run check:sync` 等价的同步硬校验，禁止直接绕过。
